How it works

Triage pairs a grounded deterministic core with an LLM that reasons over the facts — not the raw logs.

The pipeline

1. Parse. The bundle is extracted server-side and walked. Triage discovers cluster-resources JSON (pods, deployments, statefulsets, events, nodes, PVCs, configmaps, storageclasses) and pod log files, tolerating layout differences between Troubleshoot versions.

2. Detect. A catalog of deterministic detectors runs over the parsed model. Each emits findings with a severity, the affected resources, and an evidence excerpt with its source path — so nothing is asserted without proof.

3. Reason. The findings (not the megabytes of raw logs) are distilled into a compact digest and sent to an LLM acting as a senior K8s support engineer. It correlates findings into causal chains, names the most likely root cause, and writes a prioritized fix plan. With no API key, this step is replaced by a deterministic summary.

Detector catalog

Workloads

CrashLoopBackOff, OOMKilled (exit 137), high restart counts, ImagePullBackOff / ErrImagePull, CreateContainerConfigError, Pending / unschedulable pods, replica shortfalls.

Nodes

NotReady, MemoryPressure / DiskPressure / PIDPressure, kubelet not posting status, capacity vs. allocatable.

Storage

PVCs stuck Pending, missing StorageClass, no matching PersistentVolume, provisioning failures.

Config

Missing ConfigMap / Secret keys referenced by containers, env wiring errors.

Events

Warning-event aggregation by reason: FailedScheduling, BackOff, Unhealthy, FailedMount, ProvisioningFailed.

Logs

Pattern scan for panics, OOM, connection-refused, TLS/cert errors, permission denied, DB connection failures — with line counts and sample lines.

Privacy

Bundles are processed server-side and not shared with third parties beyond the optional LLM call, which receives only a distilled digest of findings and capped log excerpts — never the full archive. The bundle is read-only; Triage never touches a live cluster.
